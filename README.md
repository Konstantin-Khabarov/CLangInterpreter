Интерпретатор динамически типизированного C-подобного языка программирования, реализованный на Java с использованием JavaCC для генерации парсера.

## Архитектура

Программа проходит следующие этапы обработки:

```
Исходный код
     │
     ▼
 Лексер / Парсер (JavaCC)
     │  Parser.jj → src-gen/
     ▼
 Абстрактное синтаксическое дерево (AST)
     │  ast/*.java
     ▼
 Семантический анализ
     │  SemanticAnalyzer.java
     │  - проверка типов
     │  - вставка неявных приведений (CastNode)
     │  - проверка области видимости
     ▼
 Выполнение
     ├── Интерпретатор (по умолчанию)
     │   Interpreter.java — обход дерева
     └── Виртуальная машина (флаг -codegen)
         BytecodeGenerator.java → VirtualMachine.java
```

### Ключевые компоненты

| Компонент | Файл | Описание |
|-----------|------|----------|
| Грамматика | `src/main/javacc/Parser.jj` | JavaCC-грамматика языка |
| Точка входа | `Program.java` | Запуск, вывод AST, вызов интерпретатора |
| Интерпретатор | `runtime/Interpreter.java` | Обход AST и вычисление значений |
| Семантика | `semantic/SemanticAnalyzer.java` | Анализ типов и областей видимости |
| Контекст | `runtime/Context.java` | Таблица символов со связанными областями |
| Значения | `runtime/Value.java` | Хранение значений с типизацией |
| Встроенные ф-ции | `runtime/BuiltInFunctions.java` | Стандартная библиотека |
| Кодогенерация | `codegen/BytecodeGenerator.java` | Компилятор AST → байткод |
| ВМ | `codegen/VirtualMachine.java` | Стековая виртуальная машина |

## Синтаксис языка

### Типы данных

Язык динамически типизирован — тип переменной определяется присваиваемым значением.

| Тип | Примеры |
|-----|---------|
| `int` | `42`, `-7`, `0` |
| `double` | `3.14`, `.5`, `2.` |
| `boolean` | `true`, `false` |
| `string` | `"hello"`, `"строка\n"` |
| `array` | `[1, 2, 3]`, `[]` |
| `null` | — |

Строки поддерживают escape-последовательности: `\n`, `\t`, `\\`, `\"`.

### Переменные

Переменные объявляются неявно при первом присваивании:

```
x = 42;
name = "world";
flag = true;
arr = [1, 2, 3];
```

### Операторы

**Арифметические:** `+`, `-`, `*`, `/`, `%`

**Строковые и массивные:** `+` — конкатенация строк и массивов

**Сравнения:** `<`, `<=`, `>`, `>=`, `==`, `!=`

**Логические:** `&&`, `||`, `!`

**Унарные:** `-` (отрицание), `++`, `--` (инкремент/декремент)

**Присваивание:** `=`

**Индексация массива:** `arr[i]`

**Приоритет операторов** (от высшего к низшему):
1. Постфиксные: `arr[i]`, вызов функции `f()`
2. Унарные: `!`, `-`, `++`, `--`
3. Мультипликативные: `*`, `/`, `%`
4. Аддитивные: `+`, `-`
5. Сравнения: `<`, `<=`, `>`, `>=`
6. Равенство: `==`, `!=`
7. Логическое И: `&&`
8. Логическое ИЛИ: `||`
9. Присваивание: `=`

### Ветвление

```
if (condition) {
    // then-блок
}

if (condition) {
    // then-блок
} else {
    // else-блок
}
```

### Циклы

```
while (condition) {
    // тело
}

for (i = 0; i < n; i = i + 1) {
    // тело
}
```

### Функции

Функции объявляются ключевым словом `def`. Поддерживается рекурсия и лексическое связывание:

```
def имяФункции(параметр1, параметр2) {
    // тело
    return выражение;
}
```

Функции можно вызывать до их объявления в файле (семантический анализатор проводит предварительный сбор объявлений).

### Массивы

```
arr = [10, 20, 30];       // литерал массива
arr[0] = 99;              // запись по индексу
x = arr[1];               // чтение по индексу
n = size(arr);            // длина массива
addItem(arr, 40);         // добавление элемента в конец
empty = newArray(5);      // массив из 5 null-значений
```

Массивы гетерогенны — элементы могут иметь разные типы.

### Комментарии

```
// однострочный комментарий

/* многострочный
   комментарий */
```

## Сборка и запуск

### Требования

- Java 11+
- Maven 3.6+

### Сборка

```bash
mvn clean package
```

Собирает исполняемый JAR: `target/MathExprLangJavaCC-1.0-all.jar`

### Запуск

**Из файла:**
```bash
java -jar target/MathExprLangJavaCC-1.0-all.jar program.txt
```

**Из стандартного ввода:**
```bash
java -jar target/MathExprLangJavaCC-1.0-all.jar < program.txt
```

**Флаги командной строки:**

| Флаг | Описание |
|------|----------|
| `-nt` | Не выводить AST |
| `-codegen` | Использовать байткод-компилятор + виртуальную машину вместо интерпретатора |
| `-o <файл>` | Сохранить сгенерированный байткод в файл |

По умолчанию при запуске выводятся:
1. AST (абстрактное синтаксическое дерево) до семантического анализа
2. AST после вставки узлов неявного приведения типов
3. Результат выполнения программы

## Примеры программ

### Рекурсивная функция (числа Фибоначчи)

```
def fibonacci(n) {
    if (n <= 1) {
        return n;
    }
    return fibonacci(n - 1) + fibonacci(n - 2);
}

println(fibonacci(10));
```

### Цикл и массив

```
arr = [1, 2, 3, 4, 5];

sum = 0;
for (i = 0; i < size(arr); i = i + 1) {
    sum = sum + arr[i];
}
println(sum);
```

### Квадратный корень методом Ньютона

```
def sqrtFunc(num) {
    tolerance = 0.00001;
    guess = num;

    while (abs(pow(guess, 2) - num) > tolerance) {
        guess = (guess + num / guess) / 2;
    }
    return guess;
}

n = double(read());
if (n < 0) {
    println("Некорректный ввод");
} else {
    println(sqrtFunc(n));
}
```

### Поиск суммы между минимумом и максимумом массива

```
def solution(arr) {
    minValue = 10000000;
    maxValue = -10000000;
    minIndex = -1;
    maxIndex = -1;

    for (i = 0; i < size(arr); i = ++i) {
        if (arr[i] <= minValue) {
            minValue = arr[i];
            minIndex = i;
        }
        if (arr[i] > maxValue) {
            maxValue = arr[i];
            maxIndex = i;
        }
    }

    if (minIndex < maxIndex) {
        start = minIndex;
        end = maxIndex;
    } else {
        start = maxIndex;
        end = minIndex;
    }

    sum = 0;
    for (i = start + 1; i < end; i = ++i) {
        sum = sum + arr[i];
    }
    return sum;
}

arr1 = [17, 20, 0, 16, 20, 4, 0, 9, 9, 3];
println(solution(arr1));
```

## Виртуальная машина (байткод-режим)

При запуске с флагом `-codegen` программа компилируется в байткод и выполняется стековой виртуальной машиной вместо прямого обхода AST.

### Модель памяти ВМ

ВМ оперирует тремя структурами данных:

| Структура | Тип | Назначение |
|-----------|-----|-----------|
| `valueStack` | Стек значений (`Deque<Value>`) | Операнды вычислений и возвращаемые значения |
| `callStack` | Стек фреймов (`Deque<int[]>`) | Адреса возврата и глубина областей видимости |
| `scopes` | Список областей видимости (`List<Map>`) | Переменные: `scopes[0]` — глобальная, `scopes[top]` — локальная |

Дополнительно при загрузке байткода строятся два индекса:

- `funcTable` — имя функции → адрес первой инструкции тела
- `labelTable` — имя метки → адрес следующей инструкции

### Система команд (OpCode)

#### Помещение констант на стек

| Команда | Аргумент | Действие |
|---------|----------|----------|
| `PUSH_INT` | целое число | Помещает `int` на стек |
| `PUSH_DOUBLE` | вещественное число | Помещает `double` на стек |
| `PUSH_STRING` | строка | Помещает `string` на стек |
| `PUSH_BOOL` | `true`/`false` | Помещает `boolean` на стек |
| `PUSH_NULL` | — | Помещает `null` на стек |

#### Работа с переменными

| Команда | Аргумент | Действие |
|---------|----------|----------|
| `LOAD` | имя переменной | Читает переменную из цепочки областей видимости и помещает на стек |
| `STORE` | имя переменной | Снимает значение со стека и сохраняет в переменную |

`STORE` ищет существующую привязку по всей цепочке областей; если не нашёл — создаёт переменную в текущей (верхней) области.

#### Операции

| Команда | Аргумент | Действие |
|---------|----------|----------|
| `BINOP` | имя операции | Снимает два операнда (`v1`, `v2`), вычисляет `v1 op v2`, помещает результат |
| `UNOP` | имя операции | Снимает один операнд, применяет унарную операцию, помещает результат |
| `CAST` | имя типа | Снимает значение, приводит к указанному типу, помещает результат |

Имена операций соответствуют значениям перечислений `BinaryOpNode.BinOp` и `UnaryOpNode.UnOp` (`ADD`, `SUB`, `MUL`, `DIV`, `MOD`, `EQ`, `NEQ`, `LESS` и т.д.).

#### Работа с массивами

| Команда | Стек до → после | Действие |
|---------|----------------|----------|
| `ARRAY_NEW` | `→ []` | Создаёт пустой массив и помещает на стек |
| `ARRAY_PUSH` | `[arr, elem] → [arr]` | Снимает `elem`, добавляет в массив (который остаётся на стеке) |
| `ARRAY_GET` | `[arr, index] → [value]` | Снимает `index` и `arr`, помещает `arr[index]` |
| `ARRAY_SET` | `[arr, index, value] →` | Снимает все три, выполняет `arr[index] = value` |

#### Управление потоком

| Команда | Аргумент | Действие |
|---------|----------|----------|
| `JMP` | метка | Безусловный переход |
| `JMP_FALSE` | метка | Снимает значение; если `false` — переходит по метке |
| `CALL` | `"funcName:N"` | Вызов функции с `N` аргументами (см. ниже) |
| `RETURN` | — | Возврат из функции (см. ниже) |
| `POP` | — | Снимает верхнее значение со стека |
| `HALT` | — | Завершает выполнение программы |

#### Псевдокоманды (не выполняются, только заполняют индексы при загрузке)

| Команда | Назначение |
|---------|-----------|
| `LABEL имя` | Определяет точку перехода |
| `DEF_FUNC имя` | Отмечает начало тела функции |
| `END_FUNC` | Отмечает конец тела функции |

### Соглашение о вызовах

**Вызов функции (`CALL funcName:N`):**

1. Вызывающий код помещает `N` аргументов на стек слева направо (первый аргумент — глубже, последний — наверху).
2. `CALL` считывает аргументы со стека в правильном порядке.
3. Если функция встроенная — вызывается через Java Reflection, результат помещается на стек, управление возвращается сразу.
4. Если пользовательская — сохраняется фрейм `[адрес_возврата, глубина_scopes]` в `callStack`, аргументы помещаются обратно на стек, создаётся новая область видимости, IP прыгает в тело функции.
5. Пролог функции выполняет `STORE` для каждого параметра в обратном порядке (снимает с верхушки стека).

**Возврат из функции (`RETURN`):**

1. Снимает возвращаемое значение со стека.
2. Извлекает фрейм из `callStack` → получает адрес возврата и сохранённую глубину областей.
3. Удаляет все области видимости до сохранённой глубины (освобождает локальные переменные).
4. Помещает возвращаемое значение на стек.
5. IP устанавливается на адрес возврата.

Если функция не содержит явного `return` — байткод-генератор автоматически добавляет в конец тела `PUSH_NULL` + `RETURN`.

### Структура сгенерированного байткода:

```
JMP __main__          ; перепрыгнуть тела функций

DEF_FUNC fibonacci    ; ── тело функции fibonacci ──
STORE n               ; сохранить параметр n
LOAD n
PUSH_INT 1
BINOP LESSEQ
JMP_FALSE L0
LOAD n
RETURN
LABEL L0
LOAD n
PUSH_INT 1
BINOP SUB
CALL fibonacci:1
LOAD n
PUSH_INT 2
BINOP SUB
CALL fibonacci:1
BINOP ADD
RETURN
PUSH_NULL             ; автоматический return null
RETURN
END_FUNC

LABEL __main__        ; ── основная программа ──
PUSH_INT 10
STORE x
LOAD x
CALL fibonacci:1
CALL println:1
POP
HALT
```

### Пример: трансляция `while`-цикла

Исходный код:
```
i = 0;
while (i < 5) {
    println(i);
    i = i + 1;
}
```

Байткод:
```
PUSH_INT 0
STORE i
LABEL L0          ; начало цикла
LOAD i
PUSH_INT 5
BINOP LESS
JMP_FALSE L1      ; выход, если условие ложно
LOAD i
CALL println:1
POP
LOAD i
PUSH_INT 1
BINOP ADD
STORE i
JMP L0            ; повторить
LABEL L1          ; конец цикла
```

### Сохранение байткода в файл

С флагом `-o <файл>` сгенерированный байткод сохраняется в текстовый файл:

```bash
java -jar target/MathExprLangJavaCC-1.0-all.jar -codegen -o output.bc program.txt
```

Формат файла — по одной инструкции на строке: `ОПКОД [аргумент]`. Строки, начинающиеся с `;`, считаются комментариями.

## Система типов и неявные приведения

В арифметических выражениях со смешанными типами `int` автоматически приводится к `double` (аналогично C). Семантический анализатор вставляет узлы `CastNode` в дерево до начала выполнения.

```
x = 1 + 2.5;   // x = 3.5 (double), int 1 неявно приводится к double
```

Явное преобразование выполняется через встроенные функции:

```
n = int("42");        // строка → int
s = string(3.14);     // double → строка
d = double(5);        // int → double
```

## Области видимости

Переменные имеют лексическую область видимости: каждый блок `{}` создаёт новую область, которая видит переменные внешних областей. Функции образуют замыкания над родительской областью.
